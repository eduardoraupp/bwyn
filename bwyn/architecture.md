 Overall style                                                                                                                                                                     
                                                                                                                                                                                    
  - Modular monolith. Modules expose only explicit public APIs, and cross-module access to internals is prohibited.                                                                 
  - Frontend and backend: a Single Page Application frontend with a backend API. The backend serves the frontend only as static resources with SPA route fallback, and never renders views server-side.                                                                                                                                                              
                                                                                                                                                                                    
  Deployment modes                                                                                                                                                                  
                                                                                                                                                                                    
  - Testing and development (client-server): the frontend runs on its own as a separate process and talks to the backend over HTTP. Frontend tests must not need the backend to  serve the frontend.                                                                                                                                                             
  - Production (single runtime): the frontend build is bundled into the monolith and served from it as static resources. Production deploys as one artifact, with no separately hosted frontend.                                                                                                                                                                
  - Rule for both: the frontend must not assume a deployment mode. The backend API base URL is configurable, same-origin by default in production, so one build works in both.      
                                                                                                                                                                                    
  Backend

- Hexagonal Architecture (ports and adapters) with CQRS. Commands and queries use separate models and handlers.                                                                                                                   
  - Domain-Driven Design, isolating the core (domain and use cases) from adapters:                                                                                                                                                  
    - Domain layer: no dependency on frameworks or infrastructure.                                                                                                                                                                  
    - Application layer (command and query handlers, the use cases):                                                                                                                                                                
      - Allowed: it may use Spring in general, for example @Component, transactions and events.                                                                                                                                     
      - Forbidden: it contains no adapters (web or persistence classes) and does not depend on infrastructure.                                                                                                                      
      - External systems: it reaches them, including AI model providers, only through ports implemented in the infrastructure layer.                                                                                                
  - Enforcement: these rules are enforced by architectural fitness functions.                                                                                                                                                                                                                                                                                                              
                                                                                                                                                                                                                                    
  Frontend                                                                                                                                                                                                                          
                                                                                                                                                                                                                                    
  - Clean Architecture (layers as in the reference book), with MVVM for the presentation layer.                                                                                                                                     
  - Inversion of Control with Inversify, using annotations (decorators):                                                                                                                                                            
    - Dependencies: classes declare them with annotations and receive them by injection.                                                                                                                                            
    - Bindings: they live in a single composition root in the infrastructure layer.                                                                                                                                                 
    - Layer rule: domain and application code do not reference the container and depend only on abstractions (DIP).                                                                                                                 
  - DDD does not apply to the frontend.
